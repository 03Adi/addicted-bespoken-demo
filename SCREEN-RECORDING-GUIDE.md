# 5–10 Minute Screen Recording: Tasks 1–3

Record one clear walkthrough (Loom, Teams, or another screen recorder). Share the browser and editor, keep the cursor visible, and narrate what you are showing. The assignment theme is live; avoid making unscheduled changes during recording. Do not show passwords, access tokens, customer information, or private admin details.

## Suggested 7-minute flow

| Time | Show | Explain |
| --- | --- | --- |
| 0:00–0:30 | Introduce the assignment, GitHub repository, and live theme page | Identify the live Style Session page and the repository. |
| 0:30–2:45 | Open `/pages/style-session` on desktop, then mobile preview | Walk through the responsive hero, steps, featured collection, FAQ, and configured booking section. Explain the section-based Online Store 2.0 design and demo artwork. Note that approved testimonials were not supplied, so the empty section is hidden. |
| 2:45–4:00 | Open Theme Editor for the Style Session page and show its settings | Show that the page is editable by a merchant and point out the collection, image, Calendly, and WhatsApp settings. Keep the published theme unchanged during the recording. |
| 4:00–5:35 | Show the bespoke product template on a test product and its metafields | Explain that product details are optional metafields (fabric, production time, lapel, lining, monogram), then show the normal product purchase controls remain available. Do not invent data as though it were production-approved. |
| 5:35–6:40 | Show Task 2 attribution code or a safe tagged preview URL | Explain first-touch UTM/`fbclid` storage for 30 days and how values are passed into the configured Calendly embed / campaign name appended to WhatsApp. Disclose that a live booking and attribution test is still pending. |
| 6:40–7:15 | Briefly show the audit document and wrap up | State what is complete, what is owner-dependent, and what must be validated with a test booking/event. |

## Recording checklist

- [ ] The first frame identifies the project and shows a working storefront preview.
- [ ] Show at least one desktop and one mobile view.
- [ ] Show a merchant-editable theme setting, make a small change, and save it.
- [ ] Show the bespoke product details section on an assigned test product if product/metafield data is available. Otherwise state that the template is implemented and assignment/data verification remains pending.
- [ ] Describe attribution honestly; do not say a Calendly booking or conversion event was verified unless you actually test one.
- [ ] Keep within 5–10 minutes, with readable browser zoom and no private credentials on screen.
- [ ] Upload the final video to an interviewer-accessible link and test that link in a signed-out/private browser window.
